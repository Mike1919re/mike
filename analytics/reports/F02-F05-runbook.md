## 0. ההשערה המרכזית — F-05 ו-F-02 הם ככל הנראה אותו נזק

הטקסט `window.dataLayer = window...` **מוצג כטקסט גלוי בגוף העמוד** ונלחץ ב-4 סשנים.

קוד שנועד לרוץ ומוצג במקום זאת כתוכן משמעו דבר אחד: **תגית ה-`<script>` שעטפה אותו
אינה שם.** ב-WordPress זה קורה בדרך אחת עיקרית — הקוד הודבק לעורך תוכן
(Elementor Text Editor / עורך קלאסי / ווידג'ט טקסט) שבו WordPress **מסנן תגיות `<script>`**
כשלמשתמש אין הרשאת `unfiltered_html`. הסינון מסיר את התגית ומשאיר את גוף ה-JS כטקסט.

וכאן החיבור: כשהזרקת סקריפט נשברת חלקית — חלק מהקוד מחוץ לתגית, חלק בפנים, או תגית
`<script>` שנפתחה ולא נסגרה — **הדפדפן מנסה לפרסר את מה שנשאר כ-JavaScript ומייצר
בדיוק `unexpected token: identifier`.**

**המשמעות המעשית:** אם תמצא את מקור הטקסט הגלוי, סביר מאוד שמצאת גם את שגיאת התחביר.
**התחל מ-F-05 — הוא המפתח ל-F-02, לא להפך.**

## 1. איתור מדויק — 4 דקות

### שלב 1.1 · האם הקוד בתוך תגית או מחוצה לה

בדף הבית ובדף "צור קשר": `Ctrl+U` (view-source) ← `Ctrl+F` ← `window.dataLayer`

| מה תראה | האבחנה |
|---|---|
| הקוד **בין** `<script>` ל-`</script>` בלבד | לא זה המקור — המשך ל-1.2 |
| הקוד **מחוץ** לכל תגית סקריפט, בתוך `<p>` / `<div>` | ✅ **מצאת את F-05** |
| `&lt;script&gt;` במקום `<script>` | ✅ הקוד עבר escaping — סונן בעורך |
| `<script>` שנפתח ואין לו `</script>` תואם | ✅ **מצאת גם את F-02** |

### שלב 1.2 · מיקום מדויק של שגיאת התחביר

DevTools (`F12`) ← **Console** ← טען מחדש עם `Ctrl+Shift+R`.
לחץ על הקישור מימין להודעת השגיאה — הוא מוביל לקובץ ולשורה.

```js
// הרץ בקונסולה — מאתר סקריפטים מוטמעים חשודים בלי לגלול את כל המקור
document.querySelectorAll('script:not([src])').forEach((s, i) => {
  const t = s.textContent;
  if (/dataLayer|gtag|gtm|fbq|wa\.me|tel:/i.test(t))
    console.log('#' + i, t.length + ' תווים', t.slice(0, 120).replace(/\s+/g,' '));
});

// מאתר קוד שדלף כטקסט גלוי לגוף העמוד
[...document.querySelectorAll('p,div,span,li')]
  .filter(el => el.children.length === 0 && /window\.|dataLayer|function\s*\(/.test(el.textContent))
  .forEach(el => console.warn('טקסט קוד גלוי:', el));
```

## 3. ⚠️ חשוד עצמאי שעולה מהנתונים — WP Rocket

בדוחות היומיים 13/09 ו-14/09 תועדו סשנים פנימיים של הצוות עם הפעולות
**"Clear Used CSS (Current)"** ו**"נקה את כל המטמון"**. הצירוף הזה הוא חתימה מובהקת
של **WP Rocket** (התכונה Remove Unused CSS). כלומר קיים באתר תוסף קאשינג ואופטימיזציה
פעיל — ולזה יש שתי השלכות ישירות על שני הליקויים שלנו:

### 3.1 · `Delay JavaScript Execution` — ההסבר המדויק ביותר לכשלי ה-CTA

זו תכונה שמעכבת את כל ה-JavaScript **עד לאינטראקציה ראשונה של המשתמש**. התוצאה
המדויקת: **הלחיצה הראשונה על כפתור אינה מפעילה אותו — היא רק משחררת את טעינת ה-JS.**
הלחיצה השנייה עובדת.

השווה לראיות שנאספו:

| ממצא בנתונים | תואם ל-Delay JS? |
|---|---|
| הכפתורים נכשלים **לסירוגין**, לא תמיד | ✅ |
| אותם כפתורים **עובדים** ב-6 הקלטות השוואה | ✅ |
| הכשלים מתרחשים כשזמן הטעינה ארוך | ✅ |
| סשן עם 69 לחיצות על "חיוג מהיר" | ✅ לחיצות חוזרות עד שנתפס |
| רכיב הבורר/מחשבון לא מגיב ואז כן | ✅ אותו מנגנון |

**התאמה של שישה מתוך שישה.** זו אינה הוכחה — אבל היא ההשערה החזקה ביותר על השולחן,
והיא נבדקת בשתי דקות.

**הבדיקה:** WP Rocket ← File Optimization ← האם `Delay JavaScript Execution` מסומן?

**התיקון (אל תכבה את התכונה — היא חשובה לביצועים):** הוסף לרשימת ההחרגות
(`Excluded JavaScript Files`) את הסקריפטים שמפעילים את ה-CTA ואת הבורר. בנוסף, יישום
F-03 (`href` נטיב) **מנטרל את הבעיה מהשורש** — קישור `tel:`/`wa.me` אינו זקוק ל-JS כלל
ולכן אינו מושפע מהעיכוב.

### 3.2 · `Combine JavaScript files` / `Minify` — חשוד ל-F-02

מיזוג קבצים מחבר סקריפטים זה לזה. אם לאחד מהם חסר `;` בסוף, ההצמדה יוצרת
**בדיוק `unexpected token: identifier`**. זה גם מסביר למה השגיאה מופיעה בשבעה עמודים —
אותו קובץ ממוזג מוגש בכולם.

**בדיקת אימות (30 שניות):** WP Rocket ← כבה זמנית `Combine JavaScript files`
ו-`Minify JavaScript` ← נקה מטמון ← טען מחדש ← בדוק קונסולה.
**אם השגיאה נעלמה — מצאת את הגורם.** אז הדלק בחזרה אחד-אחד כדי לבודד.

## 4. תיקון F-05

```html
<!-- ❌ הודבק לעורך תוכן — WordPress הסיר את התגית והשאיר את הגוף כטקסט -->
window.dataLayer = window.dataLayer || [];
function gtag(){dataLayer.push(arguments);}

<!-- ✅ המקום הנכון: WPCode / Header Footer, בתוך תגית -->
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){ dataLayer.push(arguments); }
</script>
```

**שלושה כללים:**
1. קוד מדידה **לעולם לא** בעורך תוכן. רק WPCode, Custom Code, או תבנית ילד.
2. אחרי ההסרה — ודא ש-GTM עדיין נטען: `dataLayer` בקונסולה צריך להחזיר מערך.
   **אם מחקת את העותק היחיד, השבתת את המדידה.**
3. בדוק כפילות. שני סניפטי GTM באותו עמוד הם תקלה בפני עצמה.

## 5. נקודת בקרה — אימות אחרי התיקון

```js
// 1. אפס שגיאות קונסולה
console.clear(); location.reload();

// 2. ה-CTA הם קישורים אמיתיים ולא div
document.querySelectorAll('[class*="call"],[class*="whats"],[class*="wa-"],[href^="tel:"]')
  .forEach(el => console.log(el.tagName, el.getAttribute('href') || '⚠️ אין href', el));

// 3. אין קוד שדלף כטקסט
console.log(document.body.innerText.includes('window.dataLayer') ? '⚠️ עדיין גלוי' : '✅ נקי');
```

**בדיקה ידנית — קריטית:** גלוש לעמוד ב**גלישה בסתר** (מטמון נקי, כמו גולש חדש) ולחץ
**לחיצה אחת בלבד** על "חיוג מהיר" ועל "וואטסאפ". אם הלחיצה הראשונה לא עובדת והשנייה כן —
**זה Delay JS, לא באג בקוד.** חזור לסעיף 3.1.

**אימות ב-Clarity אחרי 48 שעות:** אפס Dead Clicks על "חיוג מהיר" ו"וואטסאפ";
אפס `unexpected token: identifier`; היעלמות הלחיצות על `window.dataLayer`.
